## What will be measured

Extraction accuracy per field (exact match after normalization, plus a lenient name
score), precision, recall, missing rate and **hallucination rate** (a value where the
document states none); invoice-level exact match; line-item precision/recall/F1;
confidence calibration and the auto-approve trade-off; validation precision and recall
per rule on planted errors; processing time per document and per page (p50/p90/p95)
with a per-stage breakdown; **document success rate**, **failure rate** and
**expected-failure handling**; search recall@5/10 and MRR per mode; and a grounding
ablation. Every proportion is reported with n and a 95 % Wilson interval.
Definitions are in [`eval/metrics.py`](../eval/metrics.py) and are unit-tested in
`tests/eval/test_metrics.py` on hand-built cases with known answers.

## Dataset

Generated by `python -m eval.build_dataset` with the seeded generator in
[`tools/synth/`](../tools/synth/) (seed 20261125). Every file has ground truth in
[`eval/dataset/manifest.jsonl`](../eval/dataset/manifest.jsonl), validated by a
Pydantic model, with its sha256. All content is synthetic: free LLM endpoints may log
traffic.

(Table generated from the manifest: `eval/dataset/COMPOSITION.md`.)

**Why smaller than the brief's target (148 files).** The OpenRouter account is on the
free tier without credits: 50 requests per UTC day, shared by extraction and
embeddings. Categories that cost LLM requests (PDFs, scans, images, multi-invoice
files) were reduced so the dev split fits one day and the test split the next;
categories that cost nothing (spreadsheets and CSVs are extracted by rules, invalid
files are rejected before extraction) keep their target size. With credits (1,000
requests/day) the generator can produce the full composition in one run.

**Ground truth rule.** A field's expected value is what a careful reader can determine
from the document. A field the document doesn't state (no "Bill To", no tax line, a
bare `$` with no currency code) is expected to be null; a model that fills it in is
hallucinating.

Variation: 8 layouts (classic, modern, minimal, table-heavy, European number format,
tax-inclusive, receipt, credit note); scans at 3 fixed degradation presets (rotation,
blur, noise, JPEG quality, DPI); PNG, JPEG, perspective-warped JPEG and a 2-frame
TIFF; XLSX registers with title rows, merged cells, several sheets and numeric cells;
line-item sheets; legacy XLS; CSV with 4 delimiters and 4 encodings (UTF-8, UTF-8 BOM,
cp1252, UTF-16); planted errors (wrong total, line-sum mismatch, missing invoice
number, future date, duplicate pair, PDF↔PDF conflict, PDF↔spreadsheet mismatch); and
8 invalid files (truncated, garbage, encrypted, empty, renamed executable, random
binary, decompression bomb, zip bomb).

Split: 30 % dev for tuning, 70 % test for the headline numbers, per category; pairs
(duplicates, conflicts, cross-document) stay in one split.

## How to reproduce

```bash
docker compose up -d                       # api, worker, beat, db, redis
python -m eval.run_eval --create-key       # admin key for the runner, written to .env
python -m eval.run_eval --split dev --dry-run     # quota check only
python -m eval.run_eval --split dev --no-cache    # about 19 LLM requests
python -m eval.run_eval --split test --no-cache   # about 35 LLM requests (next UTC day on the free tier)
python -m eval.run_eval --resume eval/results/<run>   # after a quota cut
pytest tests/eval -q                       # metric definitions
```

The runner uploads every file through the public API, polls until each document is
terminal, records the environment (commit, settings, models, OCR version, Docker VM
size), checks the remaining quota before starting, and checkpoints uploads and
predictions so `--resume` never uploads a file twice. `--no-cache` flushes the LLM
response cache so timings are honest.
